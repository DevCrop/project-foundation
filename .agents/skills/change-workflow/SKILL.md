# Change Workflow

일반적인 구현, 수정, 리팩터링, 의존성 또는 자동화 변경에 사용한다.

## 변경 전

1. 저장소 상태와 가까운 지침을 확인하고 사용자 변경을 식별한다.
2. 같은 책임의 기존 구현, 타입 소유 모듈, SCSS 토큰·변수·함수·Mixin을 검색한다.
3. 새 파일이나 폴더가 필요하면 독립 책임, 재사용 경계, 테스트 경계 중 해당 근거를 기록한다.
4. 새 의존성이 필요하면 목적, 기존 대안, 라이선스, 보안·유지보수 상태, 번들 또는 이미지 비용을 비교한다.

## 구현 중

- 요청 범위와 승인된 구조를 유지한다.
- 타입은 개념 소유 모듈에서 한 번 정의하고 소비자가 가져다 쓰게 한다.
- SCSS 자산은 기존 공개 API를 우선 사용하고 실제 재사용 경계가 있을 때만 확장한다.
- 사용자 변경을 덮어쓰거나 관련 없는 정리를 섞지 않는다.

## 완료 전

1. 관련 성공·실패·경계 테스트를 실행한다.
2. `node scripts/foundation.mjs verify --base <기준 브랜치>`를 실행한다.
3. 최종 diff에서 범위, 비밀값, 생성 파일, 잠금 파일, Docker·워크플로 권한을 검토한다.
4. PR에 적용 규칙 ID, 판단 근거, 새 파일·의존성 근거, 실행한 검증과 남은 위험을 기록한다.
