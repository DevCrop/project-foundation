# Architecture Selection

구조 변경, 계층 추가, MVC·MVVM·Ports and Adapters 같은 패턴 도입 요청에 사용한다.

## 조사

다음을 실제 저장소에서 확인한다.

1. 프로젝트 규모와 현재 파일 구조
2. 상태가 생성되고 변경되고 소비되는 흐름
3. 독립적으로 변하는 축과 외부 시스템 경계
4. UI 복잡도와 테스트·배포 요구
5. 현재 구조에서 이미 해결되는 문제와 반복되는 마찰

## 비교

- 패턴을 추가하지 않는 선택을 항상 포함한다.
- 모듈형, 계층형, MVC, MVVM, Ports and Adapters, Strategy, State, Observer 중 관찰된 문제와 관련된 후보만 검토한다.
- 후보마다 의존성 방향, 추가 파일 수, 장점, 비용과 제거 조건을 기록한다.
- 추천 하나와 대안 하나를 제시한다.

## 승인 경계

구조나 파일을 변경하기 전에 사용자 승인을 요청한다. 승인된 결정만 `PROJECT.md`의 Architecture 섹션에 기록한다. 패턴을 도입한 조건이 사라졌다면 유지보다 단순화를 먼저 제안한다.
